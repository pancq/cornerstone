## 二、新增「日志设置」页面

### 路由
```
/system/settings/logs
```
入口：系统设置分组 > 日志设置

### 页面布局

页面标题：日志设置
分为三个设置卡片，每个卡片独立保存。

---

### 卡片一：日志保留策略

```
标题：保留策略

字段：
- 审计日志保留天数
  类型：数字输入框 + 单位「天」
  范围：30 ~ 3650
  默认值：90
  说明文字：「超出保留天数的日志将自动清理，建议至少保留90天」

- 登录日志保留天数
  类型：数字输入框 + 单位「天」
  范围：30 ~ 3650
  默认值：180
  说明文字：「登录记录建议保留更长时间，用于安全审计」

- 自动清理
  类型：Switch 开关
  默认：开启
  说明文字：「开启后系统每天凌晨自动清理过期日志，关闭则需手动清理」

- 手动清理按钮
  文字：「立即清理过期日志」
  点击后弹出确认对话框：
  「将清理 N 天前的日志记录，此操作不可撤销，确认继续？」
  确认后执行清理，返回「已清理 N 条记录」
```

---

### 卡片二：登录安全设置

```
标题：登录安全

字段：
- 登录失败锁定
  类型：数字输入框 + 单位「次」
  范围：3 ~ 10
  默认值：5
  说明文字：「连续登录失败超过该次数后，账号锁定15分钟」

- Session 超时时间
  类型：下拉选择
  选项：30分钟 / 1小时 / 2小时（默认）/ 4小时 / 8小时 / 永不超时
  说明文字：「用户无操作超过该时间后自动退出登录」

- 允许多处同时登录
  类型：Switch 开关
  默认：开启
  说明文字：「关闭后，同一账号在新设备登录时，旧设备将被强制下线」

- 异地登录告警
  类型：Switch 开关
  默认：关闭
  说明文字：「检测到与上次登录IP归属地不同时，发送告警通知」
```

```
标题：记录级别

字段：
- 记录查询操作
  类型：Switch 开关

  说明文字：「开启后记录所有查看/列表/详情操作，日志量会大幅增加，建议仅在需要时开启」

- 记录导出操作

  默认：开启
  说明文字：「删除、回滚等高危操作需要输入密码二次确认」
```

## 三、后端实现

### 日志设置存储

日志设置存入现有 `settings` 表，key-value 格式，新增以下配置项：

```python
# 日志保留策略
"log_retention_days": 90           # 审计日志保留天数
"login_log_retention_days": 180    # 登录日志保留天数
"log_auto_cleanup": true           # 自动清理开关

# 登录安全
"login_max_attempts": 5            # 最大失败次数
"session_timeout_minutes": 120     # Session超时（分钟）
"allow_concurrent_login": true     # 允许多处登录
"alert_on_foreign_login": false    # 异地登录告警

# 记录级别
"log_query_operations": false      # 记录查询操作
"log_export_operations": true      # 记录导出操作
"log_login_operations": true       # 记录登录操作（只读，不可修改）
"require_confirm_dangerous": true  # 高危操作二次确认
```

### 新增 API 接口

追加到现有 `backend/src/api/settings.py`：

```
GET  /api/v1/settings/logs
     获取日志设置（所有配置项）
     权限：仅 super_admin

PUT  /api/v1/settings/logs
     保存日志设置
     权限：仅 super_admin
     Body: { 配置项key-value对象 }

POST /api/v1/settings/logs/cleanup
     手动触发清理过期日志
     权限：仅 super_admin
     返回：{ "deleted_count": 1234, "duration_ms": 560 }
```

### 自动清理定时任务

在现有 `backend/src/tasks/` 目录下新建或追加 `log_cleanup.py`：

```python
# 使用 APScheduler，每天凌晨3点执行
async def cleanup_expired_logs():
    """
    读取 log_retention_days 和 login_log_retention_days 配置
    删除 audit_logs 表中超出保留天数的记录
    删除 user_sessions 表中超出保留天数的记录
    log_auto_cleanup=False 时跳过执行
    执行结果写入系统日志（不写 audit_logs，避免循环）
    """
```

### Session 超时生效

在现有认证中间件中读取 `session_timeout_minutes` 配置：
- JWT 签发时 `exp` 根据此配置计算
- 配置修改后新签发的 token 立即生效，已有 token 不受影响

### 登录失败锁定

在现有登录接口中读取 `login_max_attempts` 配置（若已有硬编码5次，改为读配置）。

## 注意事项

- 菜单改动只修改前端路由配置和侧边栏组件中的 name/title 字段，不改动任何页面内容和业务逻辑
- 「智能机器人」只改页面内的区块标题文字，不改组件名和变量名
- 日志设置页面仅 super_admin 可访问，engineer 和 viewer 进入时跳转 403
- `log_login_operations` 配置项前端显示为禁用状态的开关，不允许关闭，后端也不接受该字段的修改
- 三个卡片各自独立保存（各自有保存按钮），不是整页一个保存按钮
- 手动清理操作写入 audit_logs，记录操作人、清理时间、清理条数
- Session 超时改为「永不超时」时，JWT exp 设为当前时间 + 100年
